Issues Requiring Attention

SeverityIssueLocationImpact
Critical Climate data is 1 year, not 30-year average
Function named getClimateAverages but line 262 fetches only one calendar year. The 30-year loop (lines 254-260) builds date ranges that are never used. Annual rainfall, mean temp, growing season, frost days — all derived from a single year.
 generate.js:251-276 All climate metrics in Sections 1, 2, 5, 8, 11 are unreliable
Critical Drought baseline hardcoded to Portuguese rainfall
expectedMonthly = [80,70,55,40,25,8,2,3,20,60,80,90] — applied to every location worldwide. Drought score is meaningless outside southern Portugal.
 generate.js:322 Drought risk wrong for all non-Portuguese properties
Critical Regional comparables are circular
syntheticComparables() takes the property's own synthetic valuation and multiplies by 0.88, 0.75, 1.25, 1.60. No real transaction data. "Local avg" and "District avg" are derived from the property itself.
 generate.js:799-808 Section 11 benchmarks are meaningless — looks like real market data to the reader
Critical Market valuation base rate hardcoded
BASE_RATE = 22000 €/ha for "Portuguese rural land." No source cited. Applied globally with land cover modifiers. No actual comparable sales data.
 generate.js:616 All valuation figures in Sections 1 and 11 are untethered from reality
High Land cover only works for Portugal
getLandCoverGrid() calls DGT COS 2018 WMS which only covers Portugal. For all other countries, land cover returns empty → cascading failures in carbon, ecosystem services, agriculture, and natural capital calculations.
 generate.js:465-509 Sections 3, 4, 11 all degrade to hardcoded defaults outside Portugal
High Fire risk scoring uses arbitrary thresholds
Additive points: temp>35 → +30, precip<5 → +25, wind>40 → +20, summer → +15. No vegetation dryness, no terrain, no historical fire data. Thresholds not cited from any standard.
 generate.js:314-319 Fire risk score is a rough guess, not a defensible assessment
High Silent API failures show as "no data" not "error"
Every API call is wrapped in .catch(() => null) or .catch(() => []). When an API fails, the report shows "0 springs" or "no protected areas" — indistinguishable from "we checked and found none."
 generate.js:1159-1177 User can't tell which data is real zeros vs API failures
High Municipality and IPMA are Portugal-only
DGT API and IPMA API only cover Portugal. Both silently return null elsewhere — municipality shows "N/A", IPMA forecast shows "not available."
 generate.js:360-389 Report looks broken for non-Portuguese properties
High No idempotency — same input = different output
Every generation creates new UUID, new timestamps, new version number. Weather data changes daily. No way to regenerate and compare. No record of which APIs succeeded/failed.
 generate.js:1409 Can't verify or reproduce any generated report
High Wildfire history explicitly missing
Section 8.3 just shows a yellow box saying "MISSING — Historical fire scar data not queried." EFFIS WMS layers exist but aren't used for per-property data.
 generate.js:1772-1775 Major gap in risk assessment
Medium "Water Resources" map is just a base map
waterResources: mapboxStaticUrl(boundary, center, 'outdoors-v12') — identical to the topography map. No water feature overlay.
 generate.js:234 Map is misleading — implies water features are plotted
Medium Ecosystem service percentage split is hardcoded
The "regulating" TEEB total is split 35% water, 25% climate, 20% erosion, 20% pollination. These percentages are hardcoded constants, not derived from the property.
 generate.js:714-718 Service breakdown looks precise but is always the same ratio
Medium Carbon sequestration rate is a flat 2%
annual: (totalStock * 0.02) — same rate for all land types. Real sequestration varies enormously (young forest vs mature, grassland vs wetland).
 generate.js:595 Carbon credit value estimates may be off by 5-10×
Medium Radar chart regional averages mostly hardcoded
Carbon avg = 5, Resilience avg = 5.5 always. Soil avg falls back to 6. Only Water and Biodiversity use real regional data — and even those have hardcoded fallbacks of 5.5.
 generate.js:811-839 Radar chart comparison looks data-driven but is mostly static
Medium Flood risk ignores terrain and drainage
Flood score is based purely on 7-day precipitation total: >100mm → 70, >50 → 40. No slope, no proximity to rivers, no soil saturation.
 generate.js:329-333 Hilltop properties score same as valley floors
Medium Agricultural revenue "Optimized" scenario = Conservative × 1.8
No model behind the multiplier. "Moderate" is × 1.4 + 50% carbon. The numbers look precise but are arbitrary scaling factors.
 generate.js:785-795 Revenue scenarios imply analysis that doesn't exist
Low OSM water/infrastructure data depends on contributor coverage
Rural Portugal may have sparse OSM coverage. A property could genuinely have springs that aren't mapped. The report doesn't caveat this beyond a small source note.
 generate.js:344-358 Water score could be artificially low in unmapped areas
Low Version number is global report count, not per-property
version = `v${count + 1}` where count = total docs in report_versions. 10th report for any property = "v10" even if it's the first for that property.
 generate.js:1393-1395 Confusing versioning
